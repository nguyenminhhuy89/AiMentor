# CP0 · go build, test & lint

> Summary: 15 CP0 questions on go build, test & lint (5 easy, 7 medium, 3 hard) with answers and explanations.

## Context
Part of the CP0 Onboarding & Go essentials bank. Exam questions marked ★ are in the current exam (seed exam-v1-CP0).

## Questions

### CP0-Q106 · Easy ★
Which command compiles all packages in the module?

- A. go get ./...
- B. go lint
- C. go run
- D. go build ./...

**Answer: D** — ./... means all packages under the current directory.

### CP0-Q107 · Easy
What file name marks a Go test file?

- A. Any file in /tests
- B. Ending in _test.go
- C. Ending in .spec.go
- D. Starting with test_

**Answer: B** — go test picks up *_test.go files.

### CP0-Q108 · Easy
What is the signature of a Go unit test function?

- A. func testCreateOrder()
- B. func TestCreateOrder(t *testing.T)
- C. func Test(t)
- D. func CreateOrderTest() bool

**Answer: B** — Tests start with Test and take *testing.T.

### CP0-Q109 · Easy
What does golangci-lint do?

- A. Runs integration tests on AWS
- B. Compiles Docker images
- C. Formats YAML
- D. Runs many Go linters (vet, staticcheck, errcheck...) in one pass

**Answer: D** — It is the lint step in CI.

### CP0-Q110 · Medium
What is a table-driven test?

- A. A test stored in a database table
- B. A benchmark
- C. A test that loops over a slice of cases with inputs and expected outputs
- D. A test generated by oapi-codegen

**Answer: C** — Idiomatic Go testing style.

### CP0-Q111 · Medium
Which command shows test coverage per package?

- A. go test ./... -cover
- B. go build -cover-only
- C. go cover ./...
- D. go vet -cover

**Answer: A** — -coverprofile writes a file for detailed reports.

### CP0-Q112 · Medium
What does `t.Run(tc.name, func(t *testing.T){...})` give you?

- A. A goroutine per test that never ends
- B. Named subtests that can run and fail independently
- C. Coverage reports
- D. Benchmark results

**Answer: B** — Subtests make table-driven failures easy to read.

### CP0-Q113 · Medium
What does the errcheck linter catch?

- A. Slow functions
- B. Returned errors that are ignored
- C. Spelling mistakes in comments
- D. Unused imports only

**Answer: B** — Ignored errors are a top source of bugs.

### CP0-Q114 · Medium
What is `go vet`?

- A. A test runner
- B. A formatter
- C. A tool that reports suspicious constructs like wrong Printf args
- D. A package manager

**Answer: C** — vet is included in golangci-lint.

### CP0-Q115 · Hard ★
Why measure coverage on business logic rather than on generated code?

- A. Generated code cannot be tested
- B. Generated code is not written by the team and inflates or distorts the number
- C. Coverage tools ignore business logic
- D. Generated code is always 100% covered

**Answer: B** — The DoD threshold applies to business logic.

### CP0-Q116 · Hard
A test passes alone but fails when run with others. Likely cause?

- A. The CPU is too fast
- B. Go modules are outdated
- C. Shared mutable state between tests
- D. The linter is misconfigured

**Answer: C** — Isolate state; use t.Parallel carefully.

### CP0-Q117 · Easy
What does `t.Fatalf` do?

- A. Logs the message and stops the current test immediately
- B. Panics the whole program
- C. Logs and continues
- D. Skips the test

**Answer: A** — Use t.Errorf to continue after a failure.

### CP0-Q118 · Medium ★
Where does golangci-lint read its configuration?

- A. Dockerfile
- B. .golangci.yml in the repository
- C. openapi.yaml
- D. go.mod

**Answer: B** — Keep the config versioned.

### CP0-Q119 · Hard
In CI the order of quality steps should be…

- A. test → deploy → lint
- B. scan → deploy → build
- C. lint → build → test (with race and coverage) → scan
- D. build → deploy → test

**Answer: C** — Fail fast on cheap checks first.

### CP0-Q120 · Medium
What is a test double (mock/fake) used for?

- A. Generating OpenAPI specs
- B. Doubling test coverage
- C. Running tests twice
- D. Replacing a real dependency such as DynamoDB so tests are fast and deterministic

**Answer: D** — Interfaces make doubles easy.
