# Implementation Plan: DailyReport Drive Scan

**Branch**: `001-dailyreport-drive-scan` | **Date**: 2026-11-24 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-dailyreport-drive-scan/spec.md`

## Summary

Wire the AiMentor portal's existing `scanReports()` function to the Drive DailyReport folder by ID, add unmatched/duplicate sheet detection, a scan summary panel, role-gating for the scan button, and sample-data labeling. The portal (`portal/index.html`) is a single-file vanilla-JS artifact; all changes are targeted edits to that file plus republishing the artifact.

## Technical Context

**Language/Version**: Vanilla JavaScript (ES2020) in a single HTML file; no build step

**Primary Dependencies**: `claude.use('db')` (Firestore connector), `claude.use('mcp')` (Drive connector), `claude.use('user')` (role/permission checker) — all already used in the portal

**Storage**: Firestore via the portal's existing `db` connector; `progress/<traineeId>` collection

**Testing**: Manual validation against quickstart.md scenarios; no automated test suite for this portal

**Target Platform**: claude.ai artifact (browser)

**Performance Goals**: Full-cohort scan for ≤20 trainees completes within 60 seconds (Drive reads are the bottleneck; sequential per-file reads are acceptable at this scale)

**Constraints**: All changes in `portal/index.html` only; no new files in the portal directory; no new connector capabilities beyond those already declared

**Scale/Scope**: ≤20 trainees per cohort; one scan at a time

## Changes Required in `portal/index.html`

### Change 1 — Use folder ID directly (FR-001)

Replace the name-based folder search with a direct ID query so the scan is not fragile to folder renames.

**Before (line ~403):**
```js
const fr=await drive('search_files',{query:`title contains '${qs(name)}' and mimeType = 'application/vnd.google-apps.folder'…`})
```

**After:**
```js
const DAILY_REPORT_FOLDER_ID='1iQLe_c_h2J8a5JXFZ7_7TyFb5evwA5fb';
// directly list sheets in known folder — no folder search needed
```

### Change 2 — Role gate for scan button (FR-012)

Add a role check in `scanReports()` before any Drive call. Reuse the existing `S.canWrite` gate but also check that the user has mentor/owner access (not just any editor). Until `claude.use('user')` exposes a role enum, gate on `S.canWrite` as the minimum bar (this is already how the exams tab works).

Add: disable `repBtn` on page load if `!S.canWrite`, with an explanatory tooltip.

### Change 3 — Separate unmatched from failed; add duplicate detection (FR-006, FR-007)

Refactor the per-sheet loop to build three buckets before writing:
- `matched`: `{tid, pname, f, parsed}` for sheets with a unique, roster-confirmed TraineeID
- `unmatched`: `UnmatchedEntry[]` for identity failures
- `failed`: `FailedEntry[]` for Drive read errors

Duplicate detection: after all sheets are resolved, group `matched` by `tid`. Any `tid` with 2+ entries → move all to `unmatched[]` with reason "duplicate sheets for trainee {tid}".

Remove the auto-add-to-roster logic (current lines ~421–422). Trainees not in the roster → `unmatched[]`.

### Change 4 — Scan summary panel (FR-014)

Add a `<div id="repSummary" class="card" style="display:none">` after `repMsg`, rendered post-scan. Format:
- "✓ {matched} sheet(s) updated" in pass color
- Unmatched list (if any): file title + reason
- Failed list (if any): file title + error code

Clear and re-render on each scan. `repMsg` used only for in-progress status text.

### Change 5 — Sample data badge in table (FR-008)

In `renderReports()`, add a "SAMPLE" badge after the trainee name cell for records where `p.isSample === true`. Exclude `isSample` records from KPI aggregation in `renderKPIs()`.

### Change 6 — Actionable Drive auth error message (FR-010 improvement)

Improve `driveErr()` output to distinguish auth-expired errors from folder-not-found, and suggest a concrete fix ("Re-open the portal on claude.ai and re-authorize Google Drive").
